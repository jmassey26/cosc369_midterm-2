# COSC 369 - Software Engineering I
## Project 1: Faculty Teaching & Office-Hours Schedule Generator

A C program that reads a class-schedule file and a faculty-information
file and produces, for every professor, a class-schedule table and a
derived weekly office-hours schedule, as a plain-text report and as a
CSV breakdown of every class and office-hour block.

## Building and running

Requirements: `gcc`, GNU `make`, and `ar` (all standard on the lab
Linux machines).

```bash
# Build the static library and the executable only
make

# Build (if needed) and run schedgen on the two files in data/,
# generating output/report.txt and output/report.csv
make run

# Remove object files, the static library, and the executable
make clean

# Also remove the generated report files under output/
make distclean
```

`make run` is equivalent to running the executable by hand:

```bash
./bin/schedgen data/class_schedule.txt data/faculty_info.txt \
               output/report.txt output/report.csv
```

## Input data (CTEC Fall 2026 spreadsheet)

The class data comes from `data/CTEC_Fall_2026_Schedule.xlsx`.
`make import` (needs `python3 -m pip install openpyxl`) converts it to
the two files the C program reads and prints every repair it made:

- two end times that were clearly typos (3:15 and 9:50 read as PM)
- three classes skipped: two asynchronous online courses with no
  meeting time, and one whose start and end are both 5:00 PM
- spelling variants of one instructor ("Bemley", "Bemley, J",
  "Bemley, Jesse") merged into a single person

The spreadsheet has no faculty information, so `faculty_info.txt` is
built from the instructor names with a default policy (daytime block
ends 13:00, 120-minute evening block, evening starts at 16:00). Edit
the defaults at the top of `scripts/import_xlsx.py` or edit
`faculty_info.txt` directly.

## Prolog knowledge base (Python + Prolog layer)

On top of the C program, Python and Prolog make the same data
queryable. Python reads the two input files and writes Prolog facts
(`faculty/3`, `policy/4`, `course/3`, `meets/5`). Prolog stores those
facts plus the rules in `prolog/rules.pl` and acts as the interpreter
that answers questions such as "who teaches CTEC 402.170?" or "which office
hours are on Wednesday?". The office-hours rule is written again in
Prolog, and `make verify` checks it gives the same answer as the C
program.

Extra requirements: SWI-Prolog and the `pyswip` package, installed
for the same Python that runs the scripts.

```bash
# macOS:  brew install swi-prolog      Ubuntu:  sudo apt install swi-prolog
python3 -m pip install pyswip

make facts     # input files -> prolog/facts.pl
make query     # run the sample questions
make verify    # confirm Prolog and the C program agree
python3 scripts/query.py "teaches(P, 'ctec 402.170')"   # ask your own question
```

## Input file formats

Both input files are plain pipe-delimited (`|`) text files. `#` starts
a comment line; blank lines are ignored. See the header comments in
`data/class_schedule.txt` and `data/faculty_info.txt` for the exact
column layouts, or the field documentation in `include/course.h` and
`include/faculty.h`.

To generate a schedule for different professors/courses, edit (or
replace) those two files and re-run `make run` -- no source changes or
rebuild are required, since the file paths are the only thing the
program hard-codes as command-line defaults in the Makefile.

## Design notes (see the PDF report for full explanations)

- **Modules.** Parsing (`course.c`, `faculty.c`), scheduling logic
  (`scheduler.c`), and rendering (`output.c`, plus `util.c` for small
  shared helpers) are separated so each has one job and one header.
  `main.c` only wires them together.
- **Static library.** Every module except `main.c` is compiled and
  archived into `lib/libschedgen.a`; `main.c` is compiled separately
  and linked against that archive. This is spelled out in the
  Makefile's `$(STATIC_LIB)` and `$(EXECUTABLE)` targets.
- **Office-hours rule.** Each professor's office-hours policy (the
  "office-hours table provided by the lecturer") is three fields in
  `faculty_info.txt`: how late daytime office hours run, how long an
  evening office-hour block is, and the clock time that separates
  "daytime" from "evening" classes. `scheduler.c` applies that policy
  to whatever classes a professor teaches that day. See
  `include/scheduler.h` for the exact rule and `report/` for the
  rationale.
- **Where the input files live.** Both input files are read from the
  local filesystem (paths given on the command line, defaulted to
  `data/` by the Makefile), not fetched from the Internet. The report
  explains why.
